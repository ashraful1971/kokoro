# Kokoro TTS skill

Give a terminal-capable AI agent local text-to-speech for tutorials, voiceovers,
and spoken text. Uses [Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M)
through [kokoro-onnx](https://github.com/thewh1teagle/kokoro-onnx).
No API keys, server, global package installation, or GPU required.

## Install

Install into your project (works with Claude Code, Codex, and other agents
supported by the [skills CLI](https://github.com/vercel-labs/skills)):

```sh
npx skills add ashraful1971/kokoro
```

Then ask your agent: “Use the kokoro skill to narrate this text and save it as
narration.wav.” On first use the agent runs `scripts/setup.py`, which needs
[uv](https://docs.astral.sh/uv/), Python 3.10+, and internet access to download
the model (about 354 MB). To install manually instead, see [Use with agents](#use-with-agents).

## Quick start

Clone/download this repository into a writable folder named `kokoro`.
Requires an existing Python 3.10+ and [uv](https://docs.astral.sh/uv/).
On Linux/macOS, use `python3` if `python` is unavailable; on Windows, `py -3`
can launch these scripts instead. Run these commands inside the skill folder:

```sh
python scripts/setup.py
python scripts/speak.py --text "Welcome to this tutorial." --output outputs/welcome.wav
python scripts/speak.py --list-voices
```

Setup downloads a private Python 3.12 if needed, installs packages from `uv.lock`,
and verifies the model and voices against upstream SHA-256 digests. Allow around
1 GB of disk space for the runtime, environment, caches, and full-quality model.
The first model download is about 354 MB including voices. Later generation
does not access the network. Narration stays on your machine.

Everything generated by setup lives in `.venv/`, `.cache/`, and `models/`
inside this folder. Existing Python/uv executables are reused; no global tools
are installed. If uv is missing, download its standalone release for your OS
from [astral-sh/uv](https://github.com/astral-sh/uv/releases), extract it into
this skill's `.cache/bin/`, and add that directory to PATH **for the current
terminal session only**. You do not need the system-wide uv installer.

## Use with agents

The portable entrypoint is [SKILL.md](SKILL.md), with standard `name` and
`description` frontmatter. Runtime code has no Codex/Claude SDK dependencies.

- **Codex:** place the folder at your project's `.agents/skills/kokoro/`
  ([official discovery documentation](https://learn.chatgpt.com/docs/build-skills)).
- **Claude Code:** place it at your project's `.claude/skills/kokoro/`.
- **Other agents:** use their skill directory if supported, or instruct the
  agent to read `kokoro/SKILL.md` and execute its scripts.

Ask: “Use the kokoro skill to narrate this tutorial and save tutorial.wav.”
Agents need permission to execute local commands and, during setup, download
public packages/models. Copy the **source folder** to new machines and rerun
setup there; virtual environments are not portable between machines or paths.
This repository does not register itself with any agent or modify settings.

## Voice customization

```sh
# Long tutorial, British male voice, slightly slower
python scripts/speak.py --file tutorial.txt --voice bm_george --speed 0.9 --output outputs/tutorial.wav

# Weighted blend (weights may be ratios or percentages)
python scripts/speak.py --text "A blended voice." --voice "af_heart:70,am_michael:30" --save-style outputs/my-voice.npy --output outputs/blend.wav

# Reuse the blend
python scripts/speak.py --file tutorial.txt --style outputs/my-voice.npy --output outputs/reused.wav

# Piped text (omit --text and --file to read stdin)
printf 'Hello from standard input.' | python scripts/speak.py --output outputs/stdin.wav
```

Every native synthesis control exposed by the pinned `kokoro-onnx` engine is
available: preset/custom styles, blends, speed, pronunciation language, raw
phonemes, silence trimming, sentence/clause pauses, continuous prosody, and
phoneme timing output. The pinned fp32 model includes duration data for these
advanced modes; other/custom models are checked at runtime. See the complete
[options reference](references/options.md) for flags and model requirements.
English US/UK is the supported language scope. Pitch, emotion, volume, SSML,
voice cloning, and fixed-duration narration are not native Kokoro controls.

The standard model splits long narration into phoneme chunks automatically;
audio chunks are written directly to one WAV instead of accumulating all audio
in memory. WAV output is always mono, 24 kHz, 16-bit PCM. Progress goes to
stderr, and stdout contains one JSON result with path, duration, and settings.
Output parents are created as needed; existing files require `--force`.
Input, custom model, and output files can be outside the skill folder when
you explicitly choose their paths.

## Setup and maintenance

```sh
# Verify assets and reuse the environment/package cache without internet
python scripts/setup.py --offline

# Optional smaller model (downloaded only when requested)
python scripts/setup.py --model-variant int8
python scripts/speak.py --model-variant int8 --text "Smaller model." --output outputs/small.wav
```

`fp32` (default, 326 MB), `fp16` (164 MB), and `int8` (114 MB) use the same
28 MB voices file. Smaller variants can change quality/performance. Full-quality
fp32 is the reference test target; other variants need a compatible ONNX Runtime
CPU build. Custom local model/voices/vocab/eSpeak paths are also accepted.
Custom files are trusted user inputs and have no upstream checksum guarantee.
The runtime uses basic ONNX graph optimization and synchronous chunk generation
to keep startup light and avoid asynchronous thread wakeups in restricted
agent sandboxes. Its batch adapter is tied to the locked engine version;
retest it when updating that dependency.

Failed downloads never replace a verified file. Re-running setup repairs missing
or damaged assets. Generation also verifies bundled asset checksums. Setup refuses
source builds and uses prebuilt wheels; an unsupported platform fails rather than
installing compiler/system dependencies. No `apt`, `brew`, or global `pip` steps.

To reset, remove `.venv/`, `.cache/`, and `models/` inside this folder and rerun
setup. Keep `outputs/` if you want your recordings. All four directories are
ignored by Git. Publish source files and `uv.lock`, not downloaded runtimes/models.

Dependencies are deliberately locked. Maintainers can update `pyproject.toml`
and regenerate `uv.lock` with `uv lock`, setting `UV_CACHE_DIR` and
`UV_PYTHON_INSTALL_DIR` inside this folder (as `scripts/common.py` does). Review
the dependency diff and rerun the tests before sharing an update. Model digests
in `scripts/common.py` come from the upstream GitHub release asset metadata.

## Tests and platform support

After setup:

```sh
python -m unittest discover -s tests -v
```

Use the private interpreter for real generation tests:

```sh
# Linux/macOS
KOKORO_INTEGRATION=1 .venv/bin/python -m unittest discover -s tests -v

# Windows PowerShell
$env:KOKORO_INTEGRATION = "1"
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

The integration suite blocks Python socket connections during generation and
checks short/long audio, British pronunciation selection, blended/custom voices,
raw phonemes, output protection, and error handling. Test output is temporary.
Verified on Linux x86-64 with real CPU synthesis, including continuous prosody
and phoneme timestamps. macOS and Windows are intended targets using upstream
wheels, but have not been tested
here; no blanket compatibility claim is made. Alpine/musl and platforms without
the required wheels are not supported by this setup.
